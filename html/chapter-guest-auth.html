Guest vs Authenticated — The Concept

In Laravel, every HTTP request arrives in one of two states. Understanding this split is the foundation of everything that follows.

👤
Guest User
auth()->check() === false
  • Has not logged in or registered
  • Can browse products & public pages
  • Can add to a session-based cart
  • Cannot checkout or place orders
  • Sees Login / Register in the nav
  • Redirected to /login on protected routes
  • Gets HTTP 401/403 on protected API calls
🔓
Authenticated User
auth()->check() === true
  • Has logged in via login form
  • Can browse all public pages
  • Can checkout and place orders
  • Sees their name, cart & dashboard in nav
  • Session-cart is merged on first login
  • Redirected from /login back to dashboard
  • Can access their order history & profile
How Laravel detects auth state — anywhere in your code 
// Check if user is logged in
auth()->check()     // → true  (auth user)
auth()->guest()     // → true  (guest — NOT logged in)

// Get the current user (returns null for guests)
auth()->user()      // → User model | null
auth()->id()        // → int | null

// Facade style (identical)
Auth::check()
Auth::user()
Auth::id()

Blade Directives: @guest & @auth

The simplest way to show different content to guests vs logged-in users is Blade's built-in directives. They work anywhere in your .blade.php files.

Basic @guest / @auth 
{{-- Show content ONLY to logged-in users --}}
@auth
    <p>Welcome back, {{ auth()->user()->name }}!</p>
    <a href="{{ route('dashboard') }}">My Dashboard</a>
@endauth

{{-- Show content ONLY to guests (not logged in) --}}
@guest
    <a href="{{ route('login') }}">Login</a>
    <a href="{{ route('register') }}">Register</a>
@endguest

{{-- Combined: if/else pattern --}}
@auth
    <span>Hello, {{ auth()->user()->name }}</span>
@else
    <a href="{{ route('login') }}">Login</a>
@endauth
Show "Add to Cart" vs "Login to Buy" button 
{{-- On the product detail page --}}
@auth
    {{-- Authenticated: show functional AJAX cart button --}}
    <button
        class="btn-add-cart"
        data-id="{{ $product->id }}">
        🛒 Add to Cart
    </button>
@else
    {{-- Guest: prompt them to login first --}}
    <a href="{{ route('login') }}"
       class="btn btn--ghost">
        🔒 Login to Purchase
    </a>
    {{-- OR allow guest cart (covered in Step 9) --}}
@endauth
Check specific role inside Blade 
{{-- Only show admin link to admin users --}}
@auth
    @if (auth()->user()->role === 'admin')
        <a href="/admin">⚙️ Admin Panel</a>
    @endif
@endauth

{{-- Using @can (Laravel Policies / Gates) --}}
@can('manage-products')
    <a href="/admin/products">Manage Products</a>
@endcan

Route Guards — auth & guest Middleware

Laravel ships with two key middleware aliases for this exact purpose: auth blocks guests, guest redirects already-logged-in users away from login/register pages.

routes/web.php — complete route structure 
use App\Http\Controllers;

// ── PUBLIC ROUTES (guests AND auth users) ──────────
Route::get('/',                [HomeController::class,    'index']);
Route::get('/products',       [ProductController::class, 'index']);
Route::get('/products/{id}', [ProductController::class, 'show']);
Route::get('/cart',          [CartController::class,    'index']);
Route::post('/cart/add/{product}', [CartController::class, 'add']);

// ── GUEST-ONLY ROUTES (redirect auth users away) ───
// If a logged-in user visits /login, redirect to /dashboard
Route::middleware('guest')->group(function () {
    Route::get('/login',    [LoginController::class, 'showForm']);
    Route::post('/login',   [LoginController::class, 'login']);
    Route::get('/register', [RegisterController::class, 'showForm']);
    Route::post('/register',[RegisterController::class, 'register']);
});

// ── AUTH-REQUIRED ROUTES (redirect guests to /login) 
Route::middleware('auth')->group(function () {
    Route::post('/logout',       [LoginController::class, 'logout']);
    Route::get('/dashboard',     [DashboardController::class, 'index']);
    Route::get('/orders',        [OrderController::class, 'index']);
    Route::post('/orders',       [OrderController::class, 'store']);
    Route::get('/checkout',      [CheckoutController::class, 'index']);
    Route::get('/profile',       [ProfileController::class, 'edit']);
    Route::patch('/profile',     [ProfileController::class, 'update']);
});

// ── ADMIN-ONLY ROUTES ──────────────────────────────
Route::middleware(['auth', 'admin'])->prefix('admin')->group(function () {
    Route::resource('products', Admin\ProductController::class);
    Route::resource('orders',   Admin\OrderController::class);
    Route::resource('users',    Admin\UserController::class);
});
💡
Where does guest middleware redirect to? By default it redirects to /dashboard (or whatever HOME is set to in RouteServiceProvider.php). You can change it there.

Redirect Logic — What Happens When?

Understanding the automatic redirect chains helps you debug unexpected behavior.

GUEST tries to visit /checkout
GET /checkout (guest)
auth middleware fires
auth()->check() = false
Redirect → /login
intended URL saved in session
User logs in
redirect()->intended()
→ back to /checkout ✓
AUTH USER tries to visit /login
GET /login (auth user)
guest middleware fires
auth()->check() = true
Redirect → /dashboard
(RouteServiceProvider::HOME)
app/Providers/RouteServiceProvider.php — change HOME 
class RouteServiceProvider extends ServiceProvider
{
    // Change this to redirect auth users away from /login
    public const HOME = '/dashboard';
}
Use redirect()->intended() in your LoginController 
if (Auth::attempt($credentials)) {
    $request->session()->regenerate();

    // This sends the user back to where they were trying to go
    // before being redirected to /login — e.g. /checkout
    return redirect()->intended('/dashboard');
    // Falls back to /dashboard if no intended URL was saved
}

Controller-Level Auth Checks

Sometimes you need finer control within a single controller method — showing different data or behavior depending on auth state, without redirecting the user away.

app/Http/Controllers/ProductController.php
public function show(Product $product) { $data = ['product' => $product]; if (auth()->check()) { // Logged in: show whether they've wishlisted this product $data['isWishlisted'] = auth()->user() ->wishlist ->contains($product->id); // Show personalised price (e.g. member discount) $data['price'] = $product->getMemberPrice(auth()->user()); } else { // Guest: default price, no wishlist data $data['isWishlisted'] = false; $data['price'] = $product->price; } return view('products.show', $data); }
Abort with 403 for unauthorized access 
public function show(Order $order)
{
    // Make sure auth user can only see THEIR OWN orders
    if (auth()->id() !== $order->user_id) {
        abort(403, 'You do not have access to this order.');
    }

    return view('orders.show', compact('order'));
}

// Cleaner with authorize() (uses Policies):
public function show(Order $order)
{
    $this->authorize('view', $order); // throws 403 if not owner
    return view('orders.show', compact('order'));
}

AJAX Auth Handling — JSON Responses

When a guest makes an AJAX request to a protected route, a normal redirect response won't work in JavaScript. You need to return a 401 JSON response and handle it on the frontend.

app/Http/Middleware/Authenticate.php — detect AJAX 
protected function redirectTo(Request $request): ?string
{
    // If it's an AJAX/JSON request → return null (401 JSON)
    // If it's a normal page request → redirect to /login
    return $request->expectsJson()
        ? null
        : route('login');
}
JavaScript — handle 401 from AJAX cart request
async function addToCart(productId) { const res = await fetch(`/cart/add/${productId}`, { method: 'POST', headers: { 'Content-Type': 'application/json', 'X-CSRF-TOKEN': getCsrfToken(), 'Accept': 'application/json', // ← CRITICAL for expectsJson() }, body: JSON.stringify({ quantity: 1 }), }); if (res.status === 401) { // Guest tried a protected action — prompt to login showLoginPrompt('Please log in to add items to your cart.'); return; } if (res.status === 403) { showToast('You don\'t have permission to do that.', 'error'); return; } const data = await res.json(); // Update cart badge, etc... document.getElementById('cart-badge').textContent = data.cartCount; } // Modal/toast prompt telling guest to login function showLoginPrompt(message) { const modal = document.getElementById('login-modal'); modal.querySelector('.modal-message').textContent = message; modal.style.display = 'flex'; }
📌
Always send Accept: application/json in your AJAX headers. Laravel checks $request->expectsJson() to decide whether to return a redirect (for browser requests) or a 401 JSON error (for AJAX/API requests).

Guest Cart with Sessions

A great UX improvement: let guests add items to a cart using PHP sessions before they register. We'll merge this into their DB cart upon login.

app/Http/Controllers/CartController.php — works for both 
public function add(Request $request, Product $product)
{
    // Works for BOTH guests (session) and auth users (session)
    $cart = session('cart', []);
    $id   = $product->id;

    $cart[$id] = [
        'name'     => $product->name,
        'price'    => $product->price,
        'image'    => $product->image,
        'quantity' => ($cart[$id]['quantity'] ?? 0) + 1,
    ];

    session(['cart' => $cart]);

    return response()->json([
        'message'   => 'Added!',
        'cartCount' => count($cart),
    ]);
}

public function index()
{
    // Both guests and auth users see the same cart view
    $cart  = session('cart', []);
    $total = collect($cart)->sum(
        fn($item) => $item['price'] * $item['quantity']
    );

    return view('cart.index', compact('cart', 'total'));
}
resources/views/cart/index.blade.php — guest checkout prompt 
@if(count($cart) > 0)
    {{-- Show cart items --}}
    @foreach($cart as $id => $item)
        <div class="cart-item">
            {{ $item['name'] }} × {{ $item['quantity'] }}
            — ₱{{ number_format($item['price'] * $item['quantity'], 2) }}
        </div>
    @endforeach

    {{-- Checkout button: different for guest vs auth --}}

@else

@endif

Merge Guest Cart on Login

When a guest with items in their session cart logs in, we should preserve those items rather than losing them. Hook into Laravel's Login event to do this automatically.

app/Listeners/MergeCartOnLogin.php
namespace App\Listeners; use Illuminate\Auth\Events\Login; use Illuminate\Http\Request; class MergeCartOnLogin { public function __construct(private Request $request) {} public function handle(Login $event): void { $guestCart = $this->request->session()->get('cart', []); if (empty($guestCart)) return; // Nothing to merge // Get the newly-logged-in user $user = $event->user; // If you store cart in DB, merge here: foreach ($guestCart as $productId => $item) { $user->cartItems()->updateOrCreate( ['product_id' => $productId], ['quantity' => DB::raw('quantity + ' . $item['quantity'])] ); } // Clear the session cart after merge $this->request->session()->forget('cart'); } }
app/Providers/EventServiceProvider.php — register the listener
use Illuminate\Auth\Events\Login; use App\Listeners\MergeCartOnLogin; protected $listen = [ Login::class => [ MergeCartOnLogin::class, ], ];

Custom Middleware for Complex Rules

Sometimes you need rules beyond simple auth/guest — like "only verified email users" or "only users who've completed their profile". Middleware is the right place for these.

bash — create middleware 
$ php artisan make:middleware EnsureEmailIsVerified
$ php artisan make:middleware EnsureProfileComplete
$ php artisan make:middleware AdminMiddleware
app/Http/Middleware/EnsureProfileComplete.php 
public function handle(Request $request, Closure $next): Response
{
    $user = auth()->user();

    // Guest? Let auth middleware handle it
    if (!$user) return $next($request);

    // Auth user but profile incomplete?
    if (!$user->address || !$user->phone) {
        return redirect()->route('profile.edit')
            ->with('warning', 'Please complete your profile to checkout.');
    }

    return $next($request);
}

// Then use it on checkout route:
// Route::middleware(['auth', 'profile.complete'])->get('/checkout', ...);

Testing Both Guest & Auth States

Laravel's testing helpers make it easy to simulate both guest and authenticated requests without a real browser.

tests/Feature/AccessControlTest.php 
use App\Models\User;

class AccessControlTest extends TestCase
{
    /** @test */
    public function guest_can_browse_products()
    {
        $response = $this->get('/products');
        $response->assertStatus(200); // ✓ accessible
    }

    /** @test */
    public function guest_is_redirected_from_checkout()
    {
        $response = $this->get('/checkout');
        $response->assertRedirect('/login'); // ✓ redirect to login
    }

    /** @test */
    public function auth_user_can_access_checkout()
    {
        $user = User::factory()->create();

        $response = $this->actingAs($user)->get('/checkout');
        $response->assertStatus(200); // ✓ allowed
    }

    /** @test */
    public function auth_user_cannot_view_others_orders()
    {
        $userA = User::factory()->create();
        $userB = User::factory()->create();
        $order = Order::factory()->for($userA)->create();

        // UserB tries to see UserA's order
        $response = $this->actingAs($userB)->get("/orders/{$order->id}");
        $response->assertStatus(403); // ✓ forbidden
    }

    /** @test */
    public function non_admin_cannot_access_admin_panel()
    {
        $user = User::factory()->create(['role' => 'user']);

        $response = $this->actingAs($user)->get('/admin/products');
        $response->assertStatus(403); // ✓ forbidden
    }
}

// Run tests:
// $ php artisan test
// $ php artisan test --filter AccessControlTest
