Configure .env for Database

Every Laravel project has a .env file at the root. This is where you put your database credentials. Open it and update the DB_* variables:

.env 
# Application settings
APP_NAME=LaravelShop
APP_ENV=local
APP_KEY=base64:xxxx...  # auto-set by key:generate
APP_DEBUG=true
APP_URL=http://localhost

# Database — Laragon defaults:
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=laravel_shop
DB_USERNAME=root
DB_PASSWORD=          # Laragon default is empty
💡
Create the database first! Open phpMyAdmin at http://localhost/phpmyadmin (Laragon provides this), create a new database called laravel_shop, then run migrations.
2

MySQL vs MariaDB in Laragon

Laragon ships with both MySQL and MariaDB. You can switch between them. For Laravel development they're interchangeable — same SQL syntax, same Eloquent code.

Feature MySQL 8.x MariaDB 10.x
Default Port 3306 3306
Laravel .env DB_CONNECTION=mysql DB_CONNECTION=mysql
Performance Great for large datasets Slightly faster for reads
JSON support Full JSON columns Full JSON columns
Open source Oracle-owned Community fork (100% free)
Laragon switch Menu → MySQL → Switch to MariaDB

Migrations — Create Database Tables

Migrations are version-controlled schema files. You define your table structure in PHP, and Laravel creates the SQL for you.

bash — generate migrations 
# Create model + migration + controller all at once:
$ php artisan make:model Product -mcr
$ php artisan make:model Category -mcr
$ php artisan make:model Order -mcr
$ php artisan make:model OrderItem -mcr
database/migrations/create_products_table.php 
public function up(): void
{
    Schema::create('products', function (Blueprint $table) {
        $table->id();
        $table->string('name');
        $table->text('description')->nullable();
        $table->decimal('price', 10, 2);
        $table->unsignedInteger('stock')->default(0);
        $table->string('image')->nullable();
        $table->boolean('is_featured')->default(false);
        $table->foreignId('category_id')->constrained()->cascadeOnDelete();
        $table->timestamps();
    });
}
bash — run migrations 
$ php artisan migrate

INFO  Running migrations.
✓  2024_01_01_000000_create_users_table ............... 42ms DONE
✓  2024_01_01_000001_create_categories_table ......... 38ms DONE
✓  2024_01_01_000002_create_products_table ........... 41ms DONE

# Reset and re-run all migrations:
$ php artisan migrate:fresh

# Reset + seed:
$ php artisan migrate:fresh --seed

Models & $fillable

Eloquent models represent database tables. The $fillable array defines which columns can be mass-assigned (i.e., via Product::create([...])).

app/Models/Product.php 
namespace App\Models;

use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\Factories\HasFactory;

class Product extends Model
{
    use HasFactory;

    // Columns that can be mass-assigned
    protected $fillable = [
        'name', 'description', 'price',
        'stock', 'image', 'is_featured',
        'category_id',
    ];

    // Cast price to float automatically
    protected $casts = [
        'price'       => 'float',
        'is_featured' => 'boolean',
    ];
}

Seed the Database

Use Factories and Seeders to fill your database with realistic fake data for development.

database/seeders/DatabaseSeeder.php 
public function run(): void
{
    // Create admin user
    User::factory()->create([
        'name'     => 'Admin',
        'email'    => '[email protected]',
        'password' => bcrypt('password'),
    ]);

    // Create 5 categories
    Category::factory(5)->create();

    // Create 50 products tied to categories
    Product::factory(50)->create();

    // Create 20 test customers
    User::factory(20)->create();
}

// Run it:
// $ php artisan db:seed
// $ php artisan migrate:fresh --seed

Eloquent Queries Cheat Sheet

Eloquent ORM — common queries 
// Get all products
$products = Product::all();

// Find by ID
$product = Product::find(1);
$product = Product::findOrFail(1); // throws 404 if not found

// Filter & sort
$featured = Product::where('is_featured', true)
    ->where('stock', '>', 0)
    ->orderBy('price')
    ->get();

// Eager load relationships (avoids N+1 query problem)
$products = Product::with(['category'])->paginate(12);

// Create
$product = Product::create(['name' => 'Laptop', 'price' => 999.99]);

// Update
$product->update(['stock' => 50]);

// Delete
$product->delete();

// Aggregates
$total = Product::sum('price');
$count = Product::where('stock', '>', 0)->count();

Connect Laravel to Supabase

Supabase is an open-source Firebase alternative that gives you a hosted PostgreSQL database, REST API, Auth, and Storage. Laravel connects to it just like any PostgreSQL database — no special package needed.

💡
What you need: A free Supabase account at supabase.com. The free tier gives you a full PostgreSQL database, 500MB storage, and 2GB bandwidth — more than enough to build and test your Laravel app.

Step 1 — Create a Supabase Project

  1. Go to supabase.com → click Start your project → sign in with GitHub.
  2. Click New project → give it a name (e.g. laravel-shop).
  3. Set a strong Database Password — save it somewhere safe, you'll need it.
  4. Choose a region closest to you (e.g. Southeast Asia).
  5. Click Create new project — wait ~2 minutes for provisioning.

Step 2 — Get Your Connection Credentials

In your Supabase dashboard: go to Project Settings → Database. Scroll down to Connection string and select the PHP / Laravel tab. You'll see values like these:

Supabase Dashboard — Database Settings 
# Found under: Project Settings → Database → Connection string
Host:      db.xxxxxxxxxxxx.supabase.co
Port:      5432
Database:  postgres
Username:  postgres
Password:  your-database-password

Step 3 — Install the PostgreSQL PDO Driver

Supabase uses PostgreSQL. Laragon's PHP already includes the PDO driver for pgsql, but verify it's enabled in C:\laragon\bin\php\php8.x\php.ini:

php.ini — enable pgsql (uncomment these lines) 
; Remove the semicolon from both lines:
extension=pdo_pgsql
extension=pgsql
🔁
After editing php.ini, restart Laragon: click Stop All then Start All. Verify with: php -m | findstr pgsql in Laragon's terminal.

Step 4 — Configure .env for Supabase

.env 
# Change the DB_* block to point to Supabase:
DB_CONNECTION=pgsql
DB_HOST=db.xxxxxxxxxxxx.supabase.co   # your Supabase host
DB_PORT=5432
DB_DATABASE=postgres
DB_USERNAME=postgres
DB_PASSWORD=your-database-password        # the password you set in Step 1
DB_SSLMODE=require                         # Supabase requires SSL

Step 5 — Update config/database.php for SSL

Supabase enforces SSL connections. You need to pass the SSL mode in the pgsql driver options:

config/database.php — pgsql section 
'pgsql' => [
    'driver'   => 'pgsql',
    'host'     => env('DB_HOST', '127.0.0.1'),
    'port'     => env('DB_PORT', '5432'),
    'database' => env('DB_DATABASE', 'postgres'),
    'username' => env('DB_USERNAME', 'postgres'),
    'password' => env('DB_PASSWORD', ''),
    'charset'  => 'utf8',
    'prefix'   => '',
    'schema'   => 'public',
    'sslmode'  => env('DB_SSLMODE', 'require'),  // ← add this
],

Step 6 — Test the Connection

bash — test & migrate 
# Clear cached config first:
$ php artisan config:clear

# Test the connection:
$ php artisan db:show

# Run your migrations against Supabase:
$ php artisan migrate

INFO  Running migrations.
✓  2024_01_01_000000_create_users_table ............... 312ms DONE
✓  2024_01_01_000001_create_categories_table ......... 298ms DONE
✓  2024_01_01_000002_create_products_table ........... 301ms DONE
✅
After migrations run, open your Supabase Dashboard → Table Editor — you'll see your users, products, and categories tables appear there in real time. All Eloquent queries, relationships, and seeders work exactly the same — only the DB engine changed.

Step 7 — Using Supabase Storage for File Uploads (Optional)

Supabase also provides S3-compatible object storage. Install the Flysystem S3 adapter to use it as Laravel's disk driver — perfect for storing product images.

bash — install S3 adapter 
$ composer require league/flysystem-aws-s3-v3
.env — Supabase Storage config 
# Supabase Storage credentials (Project Settings → API → S3 Connection)
FILESYSTEM_DISK=s3
AWS_ACCESS_KEY_ID=your-supabase-access-key
AWS_SECRET_ACCESS_KEY=your-supabase-secret
AWS_DEFAULT_REGION=ap-southeast-1             # match your Supabase region
AWS_BUCKET=your-bucket-name
AWS_ENDPOINT=https://xxxxxxxxxxxx.supabase.co/storage/v1/s3
AWS_USE_PATH_STYLE_ENDPOINT=true
PHP — upload a product image to Supabase Storage 
// In your ProductController store() method:
if ($request->hasFile('image')) {
    $path = $request->file('image')->store('products', 's3');
    $imageUrl = Storage::disk('s3')->url($path);
}

Connect Laravel to Firebase

Firebase is Google's platform offering a real-time NoSQL database (Firestore), Authentication, Cloud Storage, and more. Laravel connects to Firebase via the kreait/laravel-firebase package — the official, actively maintained SDK.

💡
When to use Firebase vs MySQL: Use Firebase for real-time features (live chat, notifications, live inventory), and keep MySQL/Supabase for your main relational data. They can coexist in the same Laravel project.

Step 1 — Create a Firebase Project

  1. Go to console.firebase.google.com → sign in with Google.
  2. Click Add project → name it (e.g. laravel-shop).
  3. Disable Google Analytics if you don't need it → click Create project.
  4. Once created, click Continue to enter your project dashboard.

Step 2 — Generate a Service Account Key

  1. In Firebase Console → click the ⚙️ gear icon → Project settings.
  2. Go to the Service accounts tab.
  3. Click Generate new private key → confirm → a JSON file downloads.
  4. Rename the file to firebase-credentials.json and move it to your Laravel project root (same folder as .env).
⚠️
Never commit this file to Git! Add it to your .gitignore immediately: echo "firebase-credentials.json" >> .gitignore

Step 3 — Install the Firebase SDK

bash — install kreait/laravel-firebase 
$ composer require kreait/laravel-firebase

# Publish the config file:
$ php artisan vendor:publish --provider="Kreait\Laravel\Firebase\ServiceProvider"

INFO  Publishing assets.
✓  config/firebase.php ......................... published

Step 4 — Configure .env for Firebase

.env 
# Firebase credentials — point to your service account JSON
FIREBASE_CREDENTIALS=firebase-credentials.json   # relative to project root
FIREBASE_DATABASE_URL=https://your-project-id-default-rtdb.firebaseio.com
# Find DATABASE_URL in Firebase Console → Realtime Database → Data tab

Step 5 — Enable Firestore in Firebase Console

  1. In Firebase Console → left sidebar → Firestore Database.
  2. Click Create database → choose Start in test mode (for development).
  3. Select a Cloud Firestore location → click Enable.
📌
Test mode allows all reads/writes for 30 days — fine for development. Before going live, set up proper Security Rules in the Firestore console.

Step 6 — Use Firestore in Laravel

Inject the FirestoreClient into any controller. Here's a complete CRUD example using a notifications collection:

app/Http/Controllers/NotificationController.php 
namespace App\Http\Controllers;

use Illuminate\Http\Request;
use Kreait\Firebase\Contract\Firestore;

class NotificationController extends Controller
{
    public function __construct(protected Firestore $firestore) {}

    // CREATE — add a notification document
    public function store(Request $request)
    {
        $db = $this->firestore->database();

        $db->collection('notifications')->add([
            'user_id'    => auth()->id(),
            'message'    => $request->input('message'),
            'is_read'    => false,
            'created_at' => now()->toIso8601String(),
        ]);

        return response()->json(['status' => 'created']);
    }

    // READ — fetch all notifications for current user
    public function index()
    {
        $db = $this->firestore->database();

        $docs = $db->collection('notifications')
            ->where('user_id', '=', auth()->id())
            ->documents();

        $data = [];
        foreach ($docs as $doc) {
            $data[] = ['id' => $doc->id()] + $doc->data();
        }

        return response()->json($data);
    }

    // UPDATE — mark a notification as read
    public function markRead($id)
    {
        $db = $this->firestore->database();

        $db->collection('notifications')
            ->document($id)
            ->update([['path' => 'is_read', 'value' => true]]);

        return response()->json(['status' => 'updated']);
    }

    // DELETE — remove a document
    public function destroy($id)
    {
        $db = $this->firestore->database();

        $db->collection('notifications')
            ->document($id)
            ->delete();

        return response()->json(['status' => 'deleted']);
    }
}

Step 7 — Register Routes

routes/web.php 
use App\Http\Controllers\NotificationController;

Route::middleware('auth')->group(function () {
    Route::get('/notifications',              [NotificationController::class, 'index']);
    Route::post('/notifications',             [NotificationController::class, 'store']);
    Route::patch('/notifications/{id}/read',  [NotificationController::class, 'markRead']);
    Route::delete('/notifications/{id}',      [NotificationController::class, 'destroy']);
});

Step 8 — Use Firebase Realtime Database (Optional)

For true real-time syncing (e.g. live stock updates, order status), use the Realtime Database instead of Firestore. It pushes changes to all connected clients instantly.

PHP — Realtime Database read & write 
use Kreait\Firebase\Contract\Database;

class StockController extends Controller
{
    public function __construct(protected Database $database) {}

    // Write — update product stock in real time
    public function updateStock($productId, $newStock)
    {
        $this->database
            ->getReference("products/{$productId}/stock")
            ->set($newStock);
    }

    // Read — get current stock value
    public function getStock($productId)
    {
        $snapshot = $this->database
            ->getReference("products/{$productId}/stock")
            ->getSnapshot();

        return response()->json(['stock' => $snapshot->getValue()]);
    }
}

Step 9 — Use Firebase Storage for File Uploads (Optional)

PHP — upload to Firebase Storage 
use Kreait\Firebase\Contract\Storage;

class ProductController extends Controller
{
    public function __construct(protected Storage $storage) {}

    public function store(Request $request)
    {
        $file   = $request->file('image');
        $bucket = $this->storage->getBucket();

        // Upload to Firebase Storage
        $object = $bucket->upload(
            fopen($file->getRealPath(), 'r'),
            ['name' => 'products/' . $file->getClientOriginalName()]
        );

        // Get the public URL
        $imageUrl = 'https://storage.googleapis.com/'
            . $bucket->name()
            . '/'
            . $object->name();

        // Save product with image URL to MySQL
        Product::create([
            'name'  => $request->input('name'),
            'image' => $imageUrl,
        ]);
    }
}
